# Reproducible site-build inputs and tables

`bash build/build_all.sh` verifies the twelve gitignored raw files directly read by the three tree builders and `build/site_tables.py` against `build/inputs.sha256` before replacing `data/budget.db`. The wider research workflow uses more raw files and is not covered by this release package. The earlier website plan's estimate of seventeen files was broader than the current direct dependency inventory.

A maintainer with the pinned inputs runs `python3 build/inputs.py package`. This creates `build/raw-inputs-2026-10.zip` and updates `build/inputs-archive.sha256`. Publish the ZIP as a GitHub release asset only after checking it contains no private data. The repository has no configured Git remote or published release URL yet, so fetching from a fresh clone is **not yet operational**. Once published, set `CHICAGO_BUDGET_INPUTS_URL` to the exact HTTPS GitHub release asset URL and run `bash build/fetch_inputs.sh`. The script checks the archive SHA-256 and all extracted files and rejects unexpected ZIP entries. Do not change checksums or URL without auditing and rebuilding the source inputs. The ZIP is ignored by git.

Source links (public upstream, not an assertion that the pinned ZIP has been published): City ordinance [Chicago Data Portal 6694-f78c](https://data.cityofchicago.org/Administration-Finance/Budget-2026-Budget-Ordinance-Appropriations/6694-f78c); City payments [s4vu-giwb](https://data.cityofchicago.org/Administration-Finance/Payments/s4vu-giwb), deduplication in `scripts/payments_dedupe.py` and `research/payments_dedupe.md`; CPS budget [CPS FY2026](https://www.cps.edu/about/finance/budget/budget-2026/). To link to the committed manifest and deduplication code on GitHub after a remote is configured, use `<repository-url>/blob/<commit>/build/inputs.sha256` and `<repository-url>/blob/<commit>/scripts/payments_dedupe.py`, replacing both placeholders with the actual repository URL and commit. The pinned CSVs may not match a later upstream refresh.

`build/site_tables.py` creates:

- `vendors(payee_display, is_individual, period, amount_cents, n_payments, contract_number, department, linked_node_ids)` from the two deduplicated City payment CSVs. Period keys are `city_2025` (full year) and `city_2026_payments` (partial year). Business rows are per exact payee, contract and department. Individuals are pooled into one anonymous row per period with blank contract and department. `linked_node_ids` is a JSON array of possible matching City vendor or contract boxes, not an assertion that an invoice was budget-line coded. It can be empty. Do not sum it with payment side facts or proxy estimates.
- `context(key, value, source)` from committed `data/context_resident_2026.json`. Keys include `chicago_population`, `chicago_households`, `cps_students_fy2026`, `tax_year`, `tax_composite_rate_pct`, `tax_rate_pct:<agency>` and `tax_bill_share:<group>`. `source` is JSON with an official URL and relevant year/table metadata. These tax rate shares describe the general composite rate, not the share of actual billed dollars and not a typical resident's total tax burden.

The database tables are build artifacts. The website exporter must omit individual names and raw paths, and must preserve each payment period's partial/full-year label.
